# DEFENSE — Завдання 2: Вимоги та Use Cases

## Намір і критерії (1–2 речення):
Для цього завдання було розроблено однозначні вимоги у синтаксисі EARS та сформульовано User Stories, які згодом були візуалізовані у вигляді Use Case діаграми та деталізовані через тестовані сценарії Gherkin[cite: 8, 9]. Усі представлені нотації були узагальнені й зведені в матрицю трасування для аналізу покриття бізнес-вимог та визначення меж поточного релізу[cite: 8, 9].

## Топ-3 розбіжності (spec ↔ артефакт) + коміт-виправлення:

• **Розбіжність 1:** На Use Case діаграмі етап онлайн-оплати винесено в опціональне розширення (`<<extend>>`), оскільки в специфікації замовлення може перебувати у стані очікування післяплати (виправлено зв'язок із `Payment Gateway`)[cite: 8, 9].
  * **Коміт:** `docs(spec): separate payment gateway to optional extend relationship`

• **Розбіжність 2:** Вимогу REQ-04 перефразовано під суворий синтаксис EARS (`Optional Feature`) для усунення двозначності при ініціалізації платіжної сесії[cite: 8, 9].
  * **Коміт:** `refactor(spec): update REQ-04 to strict EARS optional syntax`

• **Розбіжність 3:** У сценарії US-02 та відповідній матриці трасування додано обробку таймауту резервування залишків (REQ-05) для автоматичного скасування анульованих замовлень[cite: 8, 9].
  * **Коміт:** `feat(spec): add REQ-05 stock reservation timeout scenario`

## Ключове рішення — які альтернативи зважив і чому обрав цю (ADR):
Деталізоване обґрунтування винесення модуля бонусного кешбеку (REQ-06) поза межі першого релізу (MVP) зафіксовано у файлі `ADR.md`[cite: 8, 9].

## Перевірка — узгодженість із попередньою моделлю (як перевірив):
Узгодженість валідовано шляхом крос-аудиту між сутностями ER-моделі (Завдання 1) та Use Cases (Завдання 2)[cite: 8, 9]:
* Варіація товару `PRODUCT_ITEM` перевірена проти вимоги REQ-01 та сценарію UC-01[cite: 8, 9];
* Життєвий цикл `ORDER` відповідає процесам створення та скасування замовлень (UC-02, UC-04)[cite: 8, 9];
* Сутність `PAYMENT` повністю покриває взаємодію із зовнішнім актором `Payment Gateway` (UC-03)[cite: 8, 9].
